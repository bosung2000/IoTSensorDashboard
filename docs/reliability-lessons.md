# 신뢰성 기록 — 실제로 겪은 것과 재발 방지

> 이 문서는 **빌드가 그린인데 런타임에서 틀렸던 것**만 모은다.
> 단위 테스트로는 안 잡히고, 실행해도 조건이 맞아야만 드러나는 부류다.
>
> 새 기능을 붙이거나 화면을 고칠 때 [착수 전 체크리스트](#착수-전-체크리스트)를 먼저 훑는다.

## 2. 반복된 부류 — 이게 핵심이다

### 부류 ①: 기준이 다른 값에 같은 이름 (R-4 · R-5 · R-6 · R-7)

**계산은 전부 맞았다.** 기준이 다른 수를 나란히 놓은 것만으로 화면이 거짓말을 했다.

| 갈린 축 | 사례 |
|---|---|
| **기간** | 전체 기간(DB 행 수) ↔ 이번 세션(카운터) |
| **근거** | 핑 응답 포함 ↔ 수신 데이터만 |
| **단위** | 메시지 ↔ 이벤트 ↔ 명(사람 수) |

> 🔑 **규칙**: 두 숫자를 한 화면에 놓기 전에 묻는다 —
> **「이 둘은 같은 기간·같은 근거·같은 단위인가?」**
> 하나라도 다르면 **라벨에 적거나, 아예 놓지 않는다.**

가장 좋은 해법은 설명 문장이 아니라 **두 값을 나란히 보여주는 것**이었다.
`센서 응답률 100.00%` 옆에 `데이터 수신율 0.00%` 를 놓으면 차이가 스스로 말한다.

### 부류 ②: 한 번은 무해한 호출이 고빈도에서 흉기가 된다 (R-10 · R-11 · 그리고 센서 팜 타일)

세 번 반복됐다. 전부 같은 모양이다:

```
화면이 매 프레임 부른다  ×  그 호출이 락을 잡는다  ×  그 락을 수집·발행이 쓴다
                        ↓
            화면을 그리느라 본체가 굶는다
```

| 사례 | 프레임당 비용 |
|---|---|
| 센서 팜 타일 | 문자열 1,000개 생성 + 락 1,000회 → **화면 정지** |
| 저장소 `Count` | 900만 행 전체 스캔 × 2 → **저장 정지** |
| 헬스 순회 | 센서 1,000대 × 3 (관제실) / × 1,000 (대시보드) → **수집 굶음** |

> 🔑 **규칙**: 화면 갱신 경로에서 무언가를 부를 때 **「이걸 초당 30번 해도 되나?」**를 묻는다.
> 특히 **락을 잡는 호출**과 **O(N) 순회**는 프레임 경로에 두지 않는다.
> 필요하면 **1초 캐시**로 내리거나 **배치 API**(락 1회)로 바꾼다.

### 부류 ③: 측정 창이 신호 주기보다 짧으면 「초당」은 잴 수 없다 (R-1 · R-3)

발행이 50ms 배치인데 33ms 창에서 세면 0과 750 사이를 오간다.
정수 이벤트라 그 사이 값이 아예 없다.

> 🔑 **규칙**: 「/s」를 표시하려면 **측정 창 ≥ 신호 주기 × 2** 이상을 확보한다.
> 화면 갱신 주기와 **분리**하고, 필요하면 몇 표본 평균을 쓴다.
> 이건 값을 예쁘게 다듬는 게 아니라 **잴 수 있게 만드는 것**이다.

## 3. 검증 함정 — 실제로 밟은 것

| 함정 | 무슨 일이 났나 | 대응 |
|---|---|---|
| `dotnet test` 가 **WPF exe 를 빌드하지 않는다** | 테스트가 참조하지 않아서. 수정 후 test 만 돌리고 앱을 띄우면 **옛 바이너리**가 뜬다 | 화면 검증 전 **`dotnet build` 를 따로** 돌린다 |
| 화면 캡처가 **남의 창**을 찍는다 | `CopyFromScreen` 은 화면 픽셀을 베끼므로 가려지면 앞 창이 찍힌다(2회 실패) | `PrintWindow(hwnd, hdc, 2)` 사용. **값 판정은 캡처 말고 UIA 로 읽는다**(`x:Name` = AutomationId) |
| `Add-Type` 인라인 C# 이 죽는다 | 이 PC 의 `LIB` 에 없는 경로(VC98)가 있어 「경고를 오류로」 처리 | 스크립트 앞에서 `$env:LIB=''; $env:INCLUDE=''` |
| `.ps1` 한글이 깨진다 | PS 5.1 은 BOM 없는 UTF-8 을 ANSI 로 읽는다 | **UTF-8 BOM 필수** (`.bat` 은 반대로 ASCII 전용) |
| **디버거로 성능을 판단했다** | VS F5 에서 `20,000 목표 → 실측 896/s`(4.5%). 디버거는 JIT 최적화를 끄고 스레드 전환 비용을 키운다 | **부하·성능 측정은 반드시 디버거 없이**(`실행.bat`) |

### ⚠️ 그런데 디버거가 결함을 찾아 줬다

R-10·R-11·R-12 는 **스크립트 측정(디버거 없음)에서 세 번 모두 「정상」**이 나왔고,
**VS F5 환경에서만** 드러났다. 디버거가 틱을 밀어 `발행 건수 > 센서 수` 조건을 매번 만들어 줬기 때문이다.

> 🧭 **디버거는 원인이 아니라 확대경이었다.**
> 같은 조건은 실사용에도 온다 — DB 가 커졌을 때, CPU 를 다른 프로그램이 잡을 때, 센서가 늘 때.
> 즉 **디버거에서 터진 것은 언젠가 실사용에서 터진다.** 「디버거라서 그렇다」로 넘기지 말 것.

## 4. 「없음」이 정상으로 읽히는 화면을 조심하라

R-12 가 가장 찾기 어려웠던 이유는 **접혀서 사라진 데이터에 흔적이 없었기 때문**이다.

- 백로그 0 (밀린 게 없다)
- 과부하 폐기 0 (버린 게 없다)
- 정합 칩 `정합 OK · 유실 0`
- 그런데 **저장은 0**

정합 칩이 `Duplicate` 를 **검사하지 않아서** 전부 중복으로 접혀도 「정합 OK」라고 말했다.
그 카운터를 화면에 올리자마자 5초 만에 **22,426건**이 찍혀 원인이 드러났다.

> 🔑 **규칙**: 안심 문구(`OK`·`유실 0`·`정상`) 옆에는 **그것을 반증할 수 있는 값**이 있어야 한다.
> 반증 카운터가 없는 안심 문구는 **거짓말이 될 준비가 된 문구**다 — 평소엔 맞다가 사고 때만 틀린다.

## 5. 착수 전 체크리스트

새 화면·지표·수집 경로를 만들 때 훑는다.

**표시**
- [ ] 이 숫자 옆의 다른 숫자와 **기간·근거·단위**가 같은가? 다르면 라벨에 적었는가?
- [ ] 비율을 그린다면 **분모의 출처**는? 「있어야 할 것」인가 「이미 본 것」인가?
- [ ] 분모가 0 일 때 **100%** 가 아니라 **「측정 불가」**로 나오는가?
- [ ] 0 이 아닌 값이 반올림으로 **0 으로 그려지지** 않는가?
- [ ] 안심 문구를 쓴다면 **반증 카운터**가 화면에 있는가?
- [ ] 「아직 못 봄」과 「끊김」을 구분하는가?

**성능**
- [ ] 화면 갱신 경로의 호출을 **초당 30번** 해도 되는가?
- [ ] 그 호출이 **락**을 잡는가? 그 락을 수집·발행이 쓰는가?
- [ ] O(N) 순회가 프레임 경로에 있는가? → 1초 캐시 또는 배치 API
- [ ] 「/s」를 표시한다면 **측정 창 ≥ 신호 주기**인가?
- [ ] 레이트를 **실제 경과 시간**(Stopwatch)으로 나누는가? (타이머 간격 ✗)

**수집·저장**
- [ ] 멱등 키가 겹칠 수 있는 경로가 있는가? (같은 ID + 같은 시각)
- [ ] 밀렸을 때 **과거를 소급 생성**하지 않는가?
- [ ] 버리는 경로가 있으면 **버린 수를 세고 화면에 내는가**?

**검증**
- [ ] `dotnet build` 를 따로 돌렸는가? (test 만으로는 WPF exe 가 안 빌드된다)
- [ ] 부하 측정을 **디버거 없이** 했는가?
- [ ] 조건이 필요한 결함이라면 **소스 가드 테스트**로 못박았는가?

## 6. 관련 컴포넌트

| 파일 | 역할 |
|---|---|
| `Core/Health/SiteHealthRule.cs` | 사이트 등급 판정 — 미관측을 장애보다 **먼저** 본다 |
| `Core/Health/SensorHealthTracker.StatusesInto` | 배치 조회 — 락 1회 |
| `Core/Formatting/RateText.cs` | 「/s」 표기 — 0 이 아닌 값을 0 으로 그리지 않는다 |
| `Core/Rendering/FramePolicy.cs` | 갱신 빈도 판정 — 안 볼 때는 CPU 도 내려간다 |
| `Ui.Common/Rendering/FormattedTextCache.cs` | 텍스트 캐시 — 한 줄 보장 + 셰이핑 재사용 |
| `Mqtt/SensorFarmEngine.Tick` | 한 틱 = 명부 한 바퀴 상한 + 시각 분산 |

이 문서가 이 프로젝트의 신뢰성 기억이다.
